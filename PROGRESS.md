| D17 | 2026-09-19 | `in`/`out` are translated by the lifter into runtime calls, and unknown ports report no device rather than being stubbed per port | A dropped instruction leaves the destination register holding the previous instruction's value, which is silent and non-deterministic; a modelled port that returns zero is at least the same answer every time, and the access is counted so the log can name it. Zero is also the truthful answer on a machine with nothing pending and nothing busy, which is the rule the NV2A interrupt registers already follow. |
| D18 | 2026-09-21 | The emulated gamepad reports `bMaxPacketSize0 = 0x20`, not 8. | Eight is legal USB, but this title's driver is built for a Controller S, which reports 32. With 8 the driver consumed the first device descriptor and let its control endpoint go dormant; with 32 it runs the rest of the enumeration sequence (second port reset and all). Every other field in the descriptor already matched the real pad exactly, so the 8 was a transcription slip rather than a choice. |
| D19 | 2026-09-21 | Physical-to-virtual translation for hardware models is answered from the translations the kernel actually handed out, not by arithmetic. | `MmGetPhysicalAddress` subtracts the contiguous base inside that window and is the identity outside it, so a physical address is ambiguous: `0x3CC934` is both the physical form of contiguous `0x803CC934` and the identity form of ordinary `0x3CC934`. The OHCI model guessed "contiguous" and was wrong for exactly the buffer that mattered. Recording each translation as it is made costs a page-granular table of a few hundred entries and is right by construction; the old arithmetic stays as the fallback for addresses that never came through the kernel. |
| D20 | 2026-09-21 | The zero flag is lifted as a real variable, `_zf`, the way the carry already was. | A conditional jump that lands on a label cannot know which predecessor arrived, so the lifter fell back to `_flags` -- a variable it declares and never assigns, making the branch silently always false. `_cf` already solved this for the carry by being a real variable that survives the block boundary; `_zf` does the same for the zero flag, written by every `cmp`, `test`, `inc` and `dec`. This was not a tidy-up: an always-false branch in the Flash player's insert path destroyed every movie-load request the front end made, which is why the title never reached its menu. |
| D21 | 2026-09-23 | A switch whose jump table has been overwritten dispatches on its index instead. | The lifter reads the table at lift time to find the targets, so it already knows the index-to-target mapping and need not trust the table to survive in guest memory. The value comparison stays first, so a title that genuinely rewrites a jump table is still obeyed; only the case that would otherwise tail-jump to a non-address changes. Jump tables are the one part of an executable section the lifted code still reads at run time -- overwriting guest *code* is harmless in a static recompilation -- so this removes the only exposure that matters. |

| D22 | 2026-09-23 | `repe`/`repne` `cmps`/`scas` publish the full flag snapshot of the last pair compared (`_zf`, `_fa/_fb`, `_fcmp`, `_sf`, `_of`, `_cf` where the function needs it), leave the flags alone when `ecx` is 0, and `loop*` decrement `ecx` (patch 0009).
