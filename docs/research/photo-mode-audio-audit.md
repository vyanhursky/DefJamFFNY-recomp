# Photo Mode audio pause audit

Read-only source audit at game `8a6576d` / toolkit `d108a64` for the Photo Mode report from 2026-11-22. No audio code, build, or game run was performed for this audit.

## Finding

The freeze currently stops the fight update, not the title's audio engine. `photo_mode_freeze()` is consumed by wrappers for `sub_00079B60` and `sub_0007A8F0`; active Photo Mode returns before each generated body, while rendering continues through `sub_000796A0` / `sub_00079E40` (`src/recomp_manual.c:622-644`, `src/patches/photo_mode.c:136-142`). These are the measured fight screen tick and its sibling. An entrance is match state 3; the match's IntroExtro path is `sub_000A2EA0` (called from state dispatch, documented in `docs/research/photo-mode-scene-paths.md:19` and `docs/research/widescreen-game-cameras.md:250`). Its generated body updates the cutscene animation, cameras and callbacks; this audit found no title-audio pause/resume call in it. Freezing the fight screen's update therefore does not suspend its independent audio playback.

Ordinary in-fight pause is not a usable audio pause seam. Existing code says the pause menu makes the fight tick skip the match update, while the screen tick and HUD keep running (`src/recomp_manual.c:614-618`). The title pause child is constructed/initialized by `CCE60` / `CDDC0` and painted from `CE200`; despite `game_audio` categorization, that path is UI paint, not audio control (`docs/research/photo-mode-scene-paths.md:27`, `src/recomp_manual.c:667-676`). Its existence does not demonstrate that voices or streams are paused.

## Audio paths and available pause primitives

- The title's Xbox hardware voices use the toolkit MCPX APU voice processor. `NV1BA0_PIO_VOICE_PAUSE` (`0x140`) takes a voice handle in low 16 bits and a pause/resume action in bit 18 (`tools/xboxrecomp/src/apu/apu_regs.h:147-149`). `fe_method()` applies that action by setting/clearing `NV_PAVS_VOICE_PAR_STATE_PAUSED` for the selected handle (`apu_vp.c:340-344`). The sample fetcher checks this bit and returns before reading samples (`apu_vp.c:1100-1140`), so this hardware voice pause leaves the voice's guest descriptor/cursor in place rather than stopping and replaying it. This is the promising primitive for title voices, including streamed APU voices; it does not establish that all possible title audio uses only this path.
- The exported toolkit `apu.h` has no public enumeration or pause-all/current-voice snapshot API. It exposes only the separate DirectSound software mixer bridge: up to 64 slots, `apu_mixer_get_state()` snapshots active/looping/cursor, `apu_mixer_stop()` clears active without advancing/resetting cursor, and `apu_mixer_play()` restores playback at that cursor (`apu.h:38-76`; implementation `apu_core.c:1866-1916`). This bridge is not the same as the hardware VP voices. A stop/play snapshot would also add a race against the APU mixer thread and is not evidence that its output queue is preserved.
- `SDL_PauseAudioStreamDevice` / `SDL_PauseAudioDevice` are output-device controls, not per-title-voice controls; pausing the device would halt the whole mixed output and queue/cursor semantics differ across backends (`apu_sdl3.c:151`, `apu_sdl2.c:131-144`). Do not use this for Photo Mode.

## Thread and state constraints

Photo Mode's tick/draw hooks and `photo_mode_frame()` are reached from guest rendering/update callbacks. The existing comment explicitly requires guest calls to stay on this thread and never execute from the GPU executor's frame-end/presentation callback (`src/recomp_manual.c:676-677`; `photo_mode_frame()` invokes `guest_call()` for redraw in `src/patches/photo_mode.c:360-379`). If a solution uses guest memory or APU methods, enter/restore it from this guest thread. The APU has a separate audio/frame thread and an internal device mutex (`apu_state.h` around `MCPXAPUState`, `apu_core.c:1411+`); do not mutate the opaque device internals or call an unprotected device method from the renderer.

A correct pause/resume must snapshot which voices were already paused and only resume voices that Photo Mode itself newly paused. Otherwise an existing game pause or another subsystem's pause gets undone on exit. It must also cover both direct DSP/APU voices and any software mixer voices that the title actually uses, without stopping unrelated desktop/app output. On scene teardown/cancel, restore prior state before the device/guest voice table disappears.

## Recommendation

Do not implement an audio pause by stopping voices, stopping/restarting streams, muting the device, or calling guest functions from the GPU thread. The MCPX per-voice pause bit is cursor-preserving at the voice processor, but there is currently no audited public host API that atomically enumerates/snapshots all active VP voices and applies/restores those bits. A game-side pass over raw VP descriptors plus writes through APU MMIO would depend on undocumented integration/thread-safety details and could clobber concurrently changing voice state. Defer the change until the runtime provides a supported guest-thread-safe snapshot/pause/resume operation (or the title's native pause path is shown to already do this). The software mixer API alone is insufficient to claim a complete portable fix.
