# v0.3.0 — Gamepads, keyboard and mouse

The second M6 (PC features) release: the game reads your gamepads, keyboard and mouse, with
rumble, remapping and hot-plug.

## New

- **Gamepads through SDL3.** Xbox, DualSense, DualShock 4, Switch Pro and most other pads, wired or
  Bluetooth. Up to four players; each pad takes the lowest free player in the order it appeared.
  `backend = xinput` reads Xbox-style pads only, with no extra library.
- **The keyboard and mouse are a player of their own**, after the pads: player 2 beside a pad, player 1
  with none. `keyboard_player` also offers `merge` (into player 1's pad), `off`, or a chosen player. Mouse
  buttons and the wheel are bindable like keys; the pointer hides when idle and stays inside the window in
  full screen. W A S D and the arrow keys are the sticks, I J K L the face buttons.
- **Rumble.** The game's rumble reaches the pad of the player who is hit. The game's pulses are brief and
  faint, so they are raised to a minimum strength and length (`rumble_floor`, `rumble_min_ms`), and a pad
  buzzes for a moment when it connects (`rumble_on_connect`).
- **Hot-plug.** A pad plugged in while the game runs, even at the player-select screen, becomes a new
  controller on the console's hub, which the game sees as an ordinary hot-plug.
- **Remapping and dead zones** in `settings.ini`: any physical control can act as any Xbox control, sticks can
  be swapped, and stick dead zones and trigger thresholds are settings.
- **Focus.** Nothing is read while the game window is in the background, and held keys are released when it
  loses focus.
- A **settings.ini and keybinds** reference page lists every setting, the default keys and every key name.

See [Controllers, keyboard and mouse](../10-input.md) and [settings.ini and keybinds](../settings-reference.md).

## Build this version

```powershell
git clone --recursive --branch v0.3.0 https://github.com/vyanhursky/DefJamFFNY-recomp.git
cd DefJamFFNY-recomp
```

Follow [Build and play](../build-and-play.md) with your own supported USA Xbox dump. The first configure
downloads SDL3 (release 3.4.18, checked against a pinned hash and built statically with only its gamepad
subsystem), so it needs network access once; `-DDEFJAM_SDL3=OFF` builds without it and reads pads through
XInput. This is a **source release**: no game data, generated code or executable. Updating from v0.2.4:
rerun the build (`.\scripts\build.ps1 -Preset win-x64-release`); the lifted code does not change.

## Limits

- The keyboard counts as a controller: with a pad as player 1 the game sees two. Use `keyboard_player = merge`
  to drive the menus from the keyboard while a pad is connected, or `off` to remove it.
- One shared `[gamepad]` map applies to every pad. Rebinding is by editing `settings.ini` with the game
  closed; the overlay planned for v0.4.0 will change bindings while you play.
- There is no pointer-driven menu: the game's menus have no notion of a pointer.
- Switch Pro and DirectInput pads, three or four physical pads at once, input latency, and Proton and Steam
  Deck were not tested.

## Validation

The owner play-tested the Release build on October 6-7, 2026: an Xbox pad and a DualSense each played, the
keyboard played, a three-player Free For All used all three, an Xbox pad as player 1 with the keyboard as
player 2 worked, the game felt the same as before, and after the second round of fixes rumble was felt on
both pads and a pad plugged in later was seen.

Automated, on the same machine (Windows 11, 2560x1440 at 120 Hz):

- The full Release regression, 14 of 14 checks (57 minutes), with the golden frames matching, the four-fighter
  matches, the two-pad match and the simulation hash; after the last fixes, unit tests, the goldens, a fight, a
  four-fighter match, the combat check and the two-pad match again, 8 of 8.
- Scripted matches through the real input paths: a One on One played to its summary entirely with the keyboard,
  a match with the keyboard as player 2 beside a scripted pad, a match with two SDL virtual gamepads (rumble
  reached the pad), and a match in which a second pad is plugged in twenty seconds after launch.
- Unit tests for binding parsing and resolution, dead zones and remapping, for slot assignment, hot-plug, focus,
  the wheel and rumble against SDL's virtual gamepads, and for the settings defaults and file round trip; the
  settings reference is checked against the settings the game writes. All run in CI.

Not checked: cursor hiding and confinement in full screen (no script could see the pointer, and the owner has not reported on them).
