# v0.7.2 — HD textures in the Linux setup

The Linux setup (the Steam Deck included) now offers **Apply HD texture upscale during install**,
as the Windows and macOS setups do. No runtime code changes: the Linux game already drew texture
packs through the Vulkan renderer it shares with macOS; only the setup did not offer the option.

## Changes

- **Linux setup: the HD option.** A checkbox in the wizard, unchecked by default (with the note
  "Adds about 6.2 GB; needs extra working space. No GPU needed."), and `--hd-textures` for
  `DefJamSetup.sh --silent`. After building the game, setup makes the Lanczos 4x packs on the CPU,
  verifies them and turns them on for the first launch; turn them off or on later on the
  launcher's or F1 overlay's **Textures** page. Setup asks for 15 GiB of extra free space while it
  works. Uninstalling keeps the packs with the rest of your data.
- **The Linux payload** carries the manylinux Pillow 12.3.0 and NumPy 2.5.2 wheels the upscaler
  needs, pinned by SHA-256 in `setup/dependencies-linux.json` (about 20 MB more), and the asset check
  imports both and runs `build-hd-pack.py --help` from the bundled Python.
- **`scripts/hd-pack-digest.py`** prints one digest of a set of packs' decoded pixels, so packs made
  on different platforms can be compared when their PNG files differ only in compression.
- **Docs:** the Linux sections of the setup guide, the HD guide, the build guide and the Linux
  "READ ME FIRST" (which also no longer says the launcher and overlay are missing on Linux).

## Validation and limits

- **Steam Deck OLED, SteamOS 3.8:** the previous install was removed (setup's `--uninstall`, the Steam
  shortcut, the folders), then a fresh silent install from an XISO with `--hd-textures --steam-shortcut`
  took 14 min 48 s, of which the upscale was about 9 min 40 s on the Deck's CPU (the development PC
  takes about four minutes). It made the full set (18,971 images), enabled both packs in `settings.ini`,
  added the Steam shortcut and placed its four artwork files. The wizard shows the new checkbox.
- **The game with packs:** the packs load (`[TEXPACK] schema=1 entries=18984`); FIGHT_ON_RESULT
- **The files differ in size from the Windows and macOS packs:** 6,569,283,340 bytes against
  6,212,168,677, the same 18,971 names. The recipe is the same (Pillow 12.3.0, PNG compression 3), and
  the difference is expected from the zlib build bundled in Pillow's Linux wheel, which compresses
  differently. The pixels have not yet been compared with a Windows or macOS pack: run
  `scripts/hd-pack-digest.py` on one; the Linux pixel digest is
  `14d09aa313ef713940f620abfc663ab078a181a0a5c750c70c4eaa6c85a9de7e`.
- Disk: about 6.6 GB of packs plus about 0.8 GB of reusable work files in the data folder; on a 64 GB
  Deck, choose a data location with room (a microSD card works; on exFAT setup copies instead of
  linking, which takes longer).
- Not checked: the HD option on a desktop Linux distribution with its own toolchain; a person playing
  with packs on in handheld and docked mode.
