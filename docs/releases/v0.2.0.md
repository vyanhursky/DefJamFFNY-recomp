# v0.2.0 — Display settings and a settings file

The first M6 (PC features) release. The game now starts by itself and has
player-facing display settings.

## New

- **Direct launch.** `defjam_recomp.exe` finds the `game` folder, supplies the
  runtime switches and writes its own log. `scripts/run.ps1` still works.
- **`settings.ini`** in the data folder, written with comments on first start.
  Environment variables still override it for one run.
- **Borderless full screen** with Alt+Enter or F11, remembered between runs.
- **Resizable window** that keeps the console's 4:3 picture with black bars, or
  stretches if you prefer. The window size is remembered.
- **Render scale, scaling filter and gamma** as settings.
- **Vsync that paces the game on the display** when its refresh rate is a multiple
  of 60, and a flip-model swap chain, so a borderless window has the latency
  exclusive full screen used to be needed for.
- Sharp rendering on scaled (high-DPI) desktops.

See [Build and play](../build-and-play.md#display-settings) for the keys.

## Build this version

```powershell
git clone --recursive --branch v0.2.0 https://github.com/vyanhursky/DefJamFFNY-recomp.git
cd DefJamFFNY-recomp
```

Follow [Build and play](../build-and-play.md) with your own supported USA Xbox
dump. This is a **source release**: no game data, generated code or executable.

## Limits

- Borderless full screen only; no exclusive mode.
- `render_scale` and `gamma` take effect at the next start.
- On displays that are not a multiple of 60 Hz (90, 144, 165) the game keeps its own
  60 fps timer and `vsync` has no effect. Variable refresh is not used in a window.
- The picture is 4:3. True 16:9 is planned for a later M6 release.
- Settings are changed in the file or with the hotkeys; the in-game menu and
  the launcher come in v0.4.0.

## Known issue

- **Terrordome crashes.** A match at the Terrordome can freeze and close, most
  reliably a four-fighter Free For All within the first minutes. This is not new:
  v0.1.0 crashes in the same match at the same place. A fix is planned for a
  bug-fix release. Other venues tested do not show it.

## Validation

The owner play-tested the Release build on October 5, 2026: Story mode and One on
One and Free For All matches at render scale 3, in a window and full screen,
switching between them during a match. He reported smooth play and no display
problems, and found the Terrordome crash above.

Automated, on the same machine (Windows 11, 2560x1440 at 120 Hz):

- Release: the nine-check regression passed with the golden frames matching; a
  scripted fight held 60 frames a second with `vsync` on and off (16.67 ms median
  present interval).
- A scripted four-fighter Free For All at the default venue ran 150 seconds at 60
  frames a second; this check is now part of the regression run.
- Debug: the same regression passed apart from the new Free For All frame-rate figure
  (47 frames a second with four fighters in the unoptimised build; no crash). The
  Release build is the one to play.
- Window and full-screen switching, wide and tall windows, the settings file round
  trip and a start with no environment variables were each checked by script.
- Toolkit tests for the settings table and the presentation arithmetic pass and run
  in CI.

Not validated: displays that are not a multiple of 60 Hz, input latency, Proton and
Steam Deck.
