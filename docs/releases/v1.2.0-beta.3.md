# v1.2.0 beta 3 — saves back in one place, safer starts and closes

This is an opt-in experimental prerelease for testing custom fighters. Stable
v1.1.2 remains Latest. The app does not offer prereleases as automatic updates;
download this beta manually. Its interface reports version 1.2.0.

You need your own supported USA Xbox dump. The game-free app verifies it and
compiles locally. No game executable or game data is distributed. Fighter packs
and their converted assets are not included.

## What is new since beta 2

- **Saves stay in `save/` again, for every player.** In beta 1 and beta 2,
  enabling a fighter pack moved every later save into a private store, so
  `save/`, your own backups and the Fighter Workshop saw old data. Now saves are
  always written to `<data>/save`. Custom fighter unlocks are kept beside them
  in `<data>/fighter-state/unlocks.ini`, by pack and fighter name, so disabling
  and re-enabling a pack restores them.
- **Coming from beta 1 or beta 2 with packs enabled:** the first start moves
  your newest fighter-era saves back into `save/` once. The old `save/` folder
  is copied to `save-backup-<date>-<time>` first, and the launcher shows a
  notice. The old store is left untouched.
- **Rolling save backups.** Each launch copies `save/UserData` and
  `fighter-state` to `save-backups/<date>-<time>/`, keeping the last three and
  the first backup of each of the seven most recent days you played. Nothing is
  added when nothing changed.
- **No helper process while you play.** Packs are compiled when you enable,
  disable or update them. Play checks the compiled files and starts at once,
  without Python. If something changed, the packs are rebuilt once before the
  window opens.
- **A pack problem no longer closes the game.** If the fighter packs fail their
  start-up checks, the game starts without them and says so; your saves and
  custom unlocks are kept. Story fights with no pack enabled no longer go
  through the fighter code at all.
- **Closing the window during a save** now waits for the save to finish (at
  most five seconds) instead of cutting it off.
- **Errors you can see on macOS and Linux.** A fatal error now shows a message
  box, and the launcher's Home page shows it at the next start until you dismiss
  it, so a message hidden behind a full-screen window (Steam Deck Game Mode) is
  not lost. It is also written to `<data>/last-error.txt`.
- **Data folders with accented or non-Latin names work on Windows.** Before,
  such a folder (for example under a Windows user name with accents) stopped the
  game at start.
- **Custom songs fix from v1.1.2:** more than 36 custom songs no longer crash
  or freeze the game.
- **Groundwork for online forks:** fighter numbers and roster order no longer
  depend on install history; a fighter set digest. See
  `docs/fighter-online-contract.md`.

## Testing and limits

WINDOWS_GATE

With fighter packs enabled, the first start after a game update rebuilds the
packs before the window opens. This can take a few minutes; later starts are
immediate.

Fighter Mod Support remains experimental. Windows is the qualified platform for
this beta; it has **not yet been played on macOS, Linux or the Steam Deck**, and
those results will follow from testing of this prerelease. Known open items:
the rebuild before Play shows no progress window, and an Options save nested
inside another can write custom unlocks into the Options file (both tracked in
[#247](https://github.com/vyanhursky/DefJamFFNY-recomp/issues/247)). Known
issues carried from stable include
[memory investigation #166](https://github.com/vyanhursky/DefJamFFNY-recomp/issues/166)
and [Steam Deck replay differences #98](https://github.com/vyanhursky/DefJamFFNY-recomp/issues/98);
this beta does not close them.

Use a backup or separate test installation, and back up the complete data
folder before the first start.

Please report the exact beta and pack versions, fighters, venue, match rules and
whether the fault follows Rematch or returning to selection. Press F9 after a
problem to create a local bug bundle; review it before sharing.
