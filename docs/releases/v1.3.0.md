# v1.3.0 — Setup without Build Tools, one-folder install, disk savings and Photo Mode

Windows setup no longer needs Microsoft's C++ Build Tools: the app brings its own
compiler. Windows installs into one folder you choose, from one page. Old installs can
reclaim gigabytes of unused save-image space, and an uninstall that deletes the data
folder backs up your saves first. A controller Photo Mode freezes a fight and lets you
fly a camera around it.

You need your own supported USA Xbox dump. The game-free app verifies it and
compiles locally; no game executable, game data or texture pack is included.
Source builds use recursive tag `v1.3.0`; see the [Windows](../build-and-play.md)
and [macOS/Linux](../build-macos-linux.md) guides.

> **Release candidate status (2026-11-28):** Windows qualification is recorded below.
> macOS and Linux/Steam Deck parity and their own regressions follow on the release PR
> before publication. This file is updated when they report.

## Changes

- **No Build Tools on Windows** ([PR #313](https://github.com/vyanhursky/DefJamFFNY-recomp/pull/313),
  from the [#189](https://github.com/vyanhursky/DefJamFFNY-recomp/issues/189) spike
  [PR #312](https://github.com/vyanhursky/DefJamFFNY-recomp/pull/312)). The Windows app
  carries pinned LLVM-MinGW (UCRT, x64), CMake 3.31 and Ninja 1.11 and builds the game as
  your normal Windows user: no Visual Studio, no Windows SDK, no administrator prompt and
  no restart. Each installed version keeps its own copy of the tools (about 332 MiB).
  Updating from v1.2.4 or older switches to the bundled compiler; older payloads still
  build with Microsoft's tools.
- **One folder, one page (Windows)** ([PR #290](https://github.com/vyanhursky/DefJamFFNY-recomp/pull/290),
  contributed by **@danfreitas97** — thank you!). The first run is now a single page:
  choose the install folder and your game copy, pick Modern or Original, and select
  **INSTALL**. The app, the game it builds, your saves and settings all live in that
  folder (`game\`, `data\`), with one desktop shortcut. Move or copy the whole folder
  and the app follows it, repointing its records and its link to your dump. Uninstalling
  removes only the app's own files and keeps `data\` unless you ask for it to go. The
  install folder can be at most 70 characters long. Accents and other alphabets work.
  Installs from v1.2.0 and older keep their existing layout and are updated in place.
- **Saves are backed up before a data-deleting uninstall** ([PR #300](https://github.com/vyanhursky/DefJamFFNY-recomp/pull/300)).
  When you tick **Also delete the data folder**, setup first copies your whole save
  tree, custom fighter unlocks and settings, verifies every byte, and only then removes
  anything. The copy keeps the save images' unused space as sparse holes, so a 5 GB
  save area backs up in about a megabyte of disk.
- **Optimize disk usage** ([PR #301](https://github.com/vyanhursky/DefJamFFNY-recomp/pull/301)).
  Installs made before sparse save images can reclaim that space: **Help → Repair or
  rebuild → Optimize disk usage** inspects first, and **Optimize now** frees only blocks
  proven to be zero, then re-verifies every byte. A successful update offers it once.
  On Windows a typical old save area drops from about 5.2 GB to well under 1 MB on disk.
  *macOS and Linux show the measurement but cannot apply it yet.*
- **Photo Mode** ([PR #303](https://github.com/vyanhursky/DefJamFFNY-recomp/pull/303)).
  Press **R3 + D-pad Down** during a fight, a fight entrance, or from the pause menu to
  freeze the scene and fly a camera: move, rise and fall, four speeds, look sensitivity,
  invert Y, field of view, roll and reset; HUD/help toggles and composition guides;
  temporary brightness, venue tint, vignette and film scratches. Photos are clean PNGs at
  the game's internal resolution in `Pictures\DefJamRecompiled`, without the HUD or any
  of Photo Mode's own controls. Your saved settings are never changed. Victory scenes,
  Story cutscenes and menus are not supported yet. Controls: [docs/photo-mode.md](../photo-mode.md).

### Fixes found while qualifying this release

- **An idle title screen could stop responding (bundled-compiler builds).** Left
  untouched, the title screen loops its attract movie; after 8 to 12 loops (20 to 30
  minutes) on the new LLVM build, DirectSound could spin forever while resetting an
  AC'97 output channel. A second guest thread's write to the trapped AC'97 page left
  the reset bit in DirectSound's one read-back. The reset now completes at that read,
  as on hardware.
- **The log could grow by gigabytes after about 40 minutes.** A "log the first 20 calls"
  counter in the Xbox kernel layer wrapped after two billion calls and then logged every
  wait, about 20 MB a second. Every build reached it eventually; the new build reached it
  sooner because it runs faster. All 54 such counters now stop counting at their limit.
- **The install page shows its errors.** A refused folder (for example one over 70
  characters) printed its reason below the visible part of the page; the page now
  scrolls to the message and to the copying status.
- **Save import refuses junctions** as it already refused symbolic links, so an import
  can never be redirected outside the save folder.

## Validation and explicit limits (Windows)

Qualified on one Windows 11 PC (2026-11-27/28), on the bundled LLVM-MinGW build players
get and on the MSVC build. Details are in the release PR and in `PROGRESS.md` under D477–D499.

- **Regression:** full `regress.py` on LLVM 14/17 + 4 Windows skips; crib/gym 2/2 on a
  prepared Story fixture; replay and repeat 2/2 on both compilers; the visual check 1/1;
  `two-matches` 35/36 with the known `combat.eliminations.match2` (D479). MSVC quick 5/5.
  After the two runtime fixes: LLVM m2/m3/m4a/fight/combat (28/28)/intro 6/6 and MSVC
  quick 5/5. Unit tests with the compiler environment: all pass.
- **Idle title screen:** 50 minutes on LLVM (21 attract loops), no hang, 31 MB of log.
  Before the fixes it hung after 8–12 loops, 3 runs out of 3.
- **Photo Mode:** controller, controller-paused, entrance and both refusal probes pass on LLVM;
  controller also passes on MSVC.
- **Real installs through the packaged app:** fresh one-folder install 386 s; a 70-character
  non-ANSI folder 427 s (71 refused, with its message); move and copy of the whole folder,
  with Repair in the copy 160 s; uninstall keeping data. Update from a real v1.2.4 install
  took 239 s and kept saves and settings byte-identical. Optimize then took the save area
  from 5.24 GB to 143,910 bytes on disk. A data-deleting uninstall's backup was
  byte-identical (1.06 MB on disk). Restored into another install, it reached the main
  menu and played a fight.
- **Not covered here:** a clean Windows PC without Visual Studio (deferred to the final
  Windows re-test), physical controllers, and macOS and Linux (on the release PR).

**Known on Windows:** extracting the game copy into a folder whose name is outside the
system code page falls back from `tar` to PowerShell (about 100–150 s instead of a few
seconds). The uninstall backup goes to Documents, which may be a OneDrive folder. The app
font has no CJK glyphs, so such folder names show as boxes.
