# v1.2.1 — Authored custom-fighter victories and finger poses

Custom-fighter packs can now include the reviewed Blaze victory with authored
lip sync and a left-hand pose. This completes the compiler support needed by
packs that combine HD CAF models, custom entrance/victory audio, facial acting
and a held finger sign. Make or edit these projects with
[Fighter Workshop 0.3.1](https://github.com/vyanhursky/defjam-ffny-fighter-workshop/releases/tag/v0.3.1).

You need your own supported USA Xbox dump. The game-free app verifies it and
compiles locally; no game executable, fighter pack, recording or game data is included.

## Changes

- **Authored CAF victory lip sync** for the reviewed Blaze `CE_113A` sequence.
  Victory uses its own extro WAV and hash; entrance keeps its independent intro
  voice and mouth tracks. Body gestures, root motion, camera and other events
  are preserved.
- **Native left-finger poses** for that victory: a timed gesture or a pose held
  from beginning to end. Wrist, arm and right-hand motion remain separate.
  The compiler validates the fixed native finger channels and pose/timing bounds.
- **Blender authoring support** for the hand envelope and full-victory hold,
  plus preview-only sound-delay calibration. Preview speed/calibration does not
  change native export timing. The regular Workshop animation preview still
  omits facial/finger evaluation.
- **Compiler capability checks** let Workshop explain when a selected game is
  too old for these fields, rather than dropping the authored performance.
- **Legacy Windows setup preparation:** use the same system ZIP extractor as
  the current app, retaining PowerShell when tar is absent. Its smoke probe now
  accounts for actual preparation duration and reports failures with diagnostics.

HD CAFs, final attributes, Team artwork, authored entrances and ordinary combat
voice replacements continue to use the support introduced in 1.2.0. The new
victory/finger profiles are bounded to the reviewed donor/native rig; arbitrary
Blender rigs, graph programs and other donors are not admitted by this update.

## Downloads and updating

- Windows x64: `DefJamRecompiled-1.2.1-windows-x64.exe`.
- macOS Apple Silicon: `DefJamRecompiled-1.2.1-macos-arm64.zip`.
- Linux / Steam Deck: `DefJamRecompiled-1.2.1-linux-x86_64.AppImage`.

Each app has its SHA-256 and source/toolkit provenance. Update through the app
or download and open it. Keep the existing data folder; the update preserves
saves, settings, mods, songs and the verified dump. Fighter packs are compiled
with the updated tools when their verified cache needs rebuilding.

## Validation and limits

Runtime PR #288 passed 35 hosted CI checks, including Windows/MSVC, macOS/Linux
runtime fixtures and all three game-free app/setup builds. Fighter/compiler
checks passed 1,749 tests (37 skips); the affected native C fixtures passed 48;
14 setup status/handoff/app-contract tests passed (3 platform skips).

Focused native macOS testing of a private three-outfit project used the default
CAF outfit at Terrordome through entrance, combat, victory and results. The
204 entrance and 201 victory face/finger samples matched the exported tracks
within 1.2e-7; original and guarded saves were unchanged. All 81 replacement
combat voice streams matched the intended PCM offline, with all 685 original
retail speech members and the protected cinematic/appearance data retained.
The owner reviewed and approved the performance.

The toolkit pin remains `d108a64`. Existing 1.2.0 aggregate gameplay and real
app install/update qualifications are carried forward for unchanged native
behavior and unchanged shipped app/update code, with the focused checks above
for the new compiler/data paths. The later C change only adds optional read-only
finger diagnostics; its GCC formatting correction does not change behavior.
Release version/records and packaging do not trigger another identical full
regression. This is **not** a fresh 1.2.1 full regression or a new real
Windows/Deck install/update claim. See the
[1.2.0 qualifications](v1.2.0.md#testing-and-limits) for the original failures,
reruns and platform scope.

New victory/finger performances have not been qualified natively on every
outfit, venue or platform, nor for skip/rematch or every randomized voice slot.
Blender/export acceptance alone is not native gameplay acceptance. Timed hand
tracks are resampled at source ticks (measured donor error up to 0.8562 degrees
outside a gesture); the full-clip constant hold avoids that interpolation error.
The existing HD CAF limits (#283), memory investigation (#166), Deck replay
issue (#98) and fighter follow-ups (#247) remain open.
