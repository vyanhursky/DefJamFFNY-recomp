# v0.4.0 — Launcher and in-game overlay

The third M6 (PC features) release: a start-up launcher and an in-game settings overlay, so the settings in
`settings.ini` can be changed with a mouse, a keyboard or a gamepad without editing the file.

## New

- **A launcher** that appears every time the game starts: the display, controller, pad-button and key settings
  and a **Play** button. Settings that are read only at start-up (render scale, who plays, how many
  controllers, the pad backend) take effect for that very launch. Tick *Skip the launcher at start* to go
  straight to the game; hold **Shift** while the game starts, or start it with `--launcher`, to see it again.
- **An in-game overlay**, opened with **F1**, the pad's guide button, or both stick clicks held for half a
  second. It shows the same screen over the picture. While it is open the game keeps running but sees every
  input at rest. Full screen, window size, picture shape, filter and vsync apply as you change them.
- **One settings screen for both**, built with Dear ImGui: Display; Controllers (which pad is which player, a
  live view of each pad's sticks and buttons as the game sees them, a rumble test, dead zones, rumble
  strength); Pad buttons (choose from a list or press **Detect** and then the button); Keyboard & mouse
  (**Add** a key, a mouse button or a wheel notch; **Clear**; **Default**); General (the overlay's key and pad
  buttons, text size, show `settings.ini`, reset everything).
- Changes are saved as you make them, and anything that still needs a restart is listed at the bottom.
- `[launcher]` and `[ui]` sections in `settings.ini`; see [settings.ini and keybinds](../settings-reference.md)
  and [Launcher and overlay](../launcher-and-overlay.md).

## Build this version

```powershell
git clone --recursive --branch v0.4.0 https://github.com/vyanhursky/DefJamFFNY-recomp.git
cd DefJamFFNY-recomp
```

Follow [Build and play](../build-and-play.md) with your own supported USA Xbox dump. The project now also
builds a small amount of C++ (the launcher and overlay), and the first configure downloads Dear ImGui (release
1.92.9b, MIT, checked against a pinned hash) as well as SDL3, so it needs network access once. This is a
**source release**: no game data, generated code or executable. Updating from v0.3.0: rerun the build
(`.\scripts\build.ps1 -Preset win-x64-release`); the lifted code does not change.

## Limits

- `render_scale` and the brightness curve still take effect at the next start (the screens say so); live render
  scale was not attempted.
- The overlay does not pause the game.
- A pad that SDL does not know as a gamepad cannot navigate the menus (the mouse and keyboard can).
- The launcher and overlay are not built or tested in hosted CI, which has no game; the settings, the rule for
  when the launcher shows and the input layer's menu hooks are.

## Validation

The owner play-tested the Release build on October 7, 2026: the launcher and its options worked before
launch and in the game, skipping the launcher worked, window resizing worked, and the keyboard shortcuts
worked.

Automated, on the same machine (Windows 11, 2560x1440 at 120 Hz):

- In the real game, by clicking through it: the launcher's pages, a captured key binding saved to
  `settings.ini`, Play, the F1 overlay over the picture, window size and full screen changed live, close; and a
  virtual gamepad opening (both stick clicks) and closing (B) the overlay during a fight.
- Unit tests: the rule for when the launcher shows (every launch, skip, Shift, `--launcher`, `--no-launcher`,
  test runs), the new settings and defaults, that the settings reference names every setting, and that the
  input layer holds the game at rest while a menu is open and still allows a rumble test. They run in CI.
- The quick regression, 5 of 5, and the full Release regression: 12 of 14 on the first run, the two failures
  (`crib`, `gym`) being the Story routes picking a different profile after a profile was added to the save
  area; with the routes updated both pass, and the other twelve checks, including the four-fighter, two-pad and
  simulation-hash checks, passed with the overlay hook in the present step.
